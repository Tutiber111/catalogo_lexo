# Salesperson dashboard

Click **Mi gestión** beside the LEXO heading while signed in with a `salesman` account. This button occupies the same navigation position as **Admin** for administrators. The dashboard opens in a full-screen dialog, with a close button and Escape support, and refreshes when opened or when an order changes while it is open. It is no longer embedded in Profile.

Administrators open **Admin → Panel de vendedores**. The admin-only dashboard lists configured salespeople by code and name. Select one to see that person's assigned clients and the clients' catalog orders, including period totals, client history, purchased products, and products not bought. It starts on **Todos los clientes** and resets client search when switching salespeople. Salespeople cannot open the admin selector. Admin access follows the existing admin role; the salesperson view remains limited to the signed-in account's code.

The initial client filter is **Sin pedidos · 30 días**. One-click buttons switch to all clients, recent activity, or no recorded orders. Clients are sorted with no recorded orders first, then oldest activity first, and show days since the last recorded order. Search and the selected filter survive refreshes within the same account. On smaller screens, the client list and recent orders stack vertically.

The activity selector supports 7, 15, 30, 45, 60, 90, 180, and 365 days, all recorded history, or **Fechas personalizadas**. Custom ranges have **Desde** and **Hasta (inclusive)** fields and an **Aplicar fechas** button. Both boundary days use the browser's local calendar dates; reversed, missing, invalid and future dates are rejected. This controls order totals, charts, recent orders and client activity filters. Historical activity uses any valid purchase within the range, even when a client's latest purchase is outside it. Search matches name, legal name, client code, and locality, ignoring accents. Click a client's name to open their detail view; it starts with their complete history regardless of the summary's selected period and has its own custom date range.

Both salesperson and admin dashboards, plus individual client details, include an order-value trend chart, brand-purchase bars, average order value, units, active buyers, repeat buyers, top products, brand buyer reach and visible catalog coverage. Trend intervals adapt to the range (daily, weekly, monthly or yearly), include zero-order intervals and expose a data table. Brand shares use line-item amounts, while the total and average use order amounts. Missing line items and differing totals are identified. Brand attribution uses the existing catalog ID/SKU matching rules; unresolved historical products are grouped as **Sin marca identificada**. Coverage deduplicates visible products by SKU and brand and shows unpurchased brands/products as opportunities for the selected period. Charts use native SVG/CSS and retain the existing permission boundaries.

Client details have three sections: all orders with expandable line items; purchased products with quantities, order value, and last order date; and visible current-catalog products without purchases in the selected period. Product search matches SKU, name, and brand. All-history mode means no recorded purchase; a shorter period means no purchase within that period. Hidden catalog products are omitted from opportunities, while historical purchased products remain visible even if removed from the catalog. SKU matching tolerates changed page IDs and deduplicates repeated entries for the same SKU and brand.

**Data scope:** salespeople can read orders they submitted plus orders for clients currently assigned to their salesperson code, regardless of who submitted them. Client ID takes precedence over text codes; legacy orders with no client ID can match by sales-client code or customer-client code. Orders with no identifying client ID/code cannot be attributed by name and remain visible only under existing ownership/admin rules. This covers records in the catalog database, not unimported ERP history. Draft and cancelled orders remain in history but are excluded from totals and product purchases. Amounts represent submitted order value, not collected revenue.

Client and order queries are paginated. Migration `supabase/migrations/20261006131341_salesperson_client_history.sql` adds explicitly assigned-client SELECT policies for orders and items. It was applied to the connected database; no write permissions were added. Accounts without a salesperson code see an assignment notice and their own orders. Errors show a retry action instead of misleading zero totals. Dashboard data is held in memory and cleared on sign-out or account changes; stale requests cannot repopulate another account's dashboard.

Selecting **Create order** uses the existing cart and client-selection flow. Switching clients is blocked while a cart contains products for a different or unspecified client. Recent orders open the existing order-detail and repeat-order interface.
